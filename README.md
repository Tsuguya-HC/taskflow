# taskflow

非決定論なエージェントの仕事を、決定論的な制御の下に置くための設計。

ワークフローエンジンとの違いは**ステップが決定論的かどうか**の一点にある。Argo のような
エンジンは「同じ入力なら同じ出力」を暗黙に仮定していて、リトライが意味を持つのもその仮定があるから。
ここで扱うステップは**嘘をつくし、毎回違うことを言う**。

## 状態

**設計と実測のみ。実装はまだ無い。** 検証は home-cluster 上の Argo Workflows で行っている。

CRD とコントローラを書くかどうかは**未決**。[Discussions](../../discussions) を参照。

## 中身

- [docs/design.md](docs/design.md) — 設計と、その根拠になった実測

## 検証済みのもの（Argo 上で実動）

| 機構 | 内容 |
|---|---|
| 判定をディレクトリで表す | `out/{pass,rework,escalate}` に置く。回収側は `ls` するだけで発話を読まない |
| 語彙をパーミッションで強制 | `out/` を別 uid の 0555 にすると、4 つ目の分類が `mkdir` の時点で作れない |
| fail-closed | 非空がちょうど 1 つでなければ `indeterminate` → 人間。判定不能を承認に倒さない |
| 根拠の併記要求 | 主張とそれを確かめた手順を対で書かせる。確かめていないものは「未確認」と明記させる |
| 成功判定の強度 | `Succeeded` が証明するのは「プロセスが 0 で終了した」ことだけ。書き込みパスを通して保存先で確認する |

## 測って分かったこと

- **指示は守る、事実は忘れる。** 検証の要求は 3/3 守られ、微妙な事実の想起は 3 回中 1 回
- **失敗は自己申告されない。** 誤答はすべて整形され、根拠を挙げ、表まで付いていた
- **観測は自分自身についての証拠であって、そこから推論した機構の証拠ではない**
